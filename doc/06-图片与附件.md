# 06 · 图片与附件

角色头像、世界书配图都存在 `content/assets/`，走「文件即真源」的同一套逻辑。

---

## 目录与格式

```
content/assets/
  ├─ chr-lx8f2a1b.png    角色头像（前缀 chr）
  ├─ wb-k2m9p3qr.png     世界书配图（前缀 wb）
  └─ img-...             其它
```

支持格式：**PNG / JPEG / WebP / GIF**

| 限制 | 值 |
|---|---|
| 单张大小上限 | 8 MB |
| 头像压缩后最长边 | 512 px |
| 配图压缩后最长边 | 1280 px |

上传前前端会先用 canvas 缩放重编码，手机拍的 5MB 照片通常能压到几百 KB。

---

## 存储的是「相对路径」

数据库/JSON 里存的是 `assets/chr-xxx.png`，不是完整 URL。

**为什么要这样**：

- 换域名、换端口不用改数据
- 可以整个 `content/` 目录拷到别的实例
- 导出的角色卡在别的实例导入后，只要 `assets/` 一起带过去就能显示

**代价**：迁移时必须连 `content/assets/` 一起拷。缺图不会报错，会回落到图标。

---

## 接口

### 上传

```
POST /api/assets
Content-Type: application/json

{ "data": "data:image/png;base64,iVBOR...", "prefix": "chr" }
```

返回：

```json
{ "path": "assets/chr-lx8f2a1b.png", "size": 24512 }
```

- `data` 支持 data URL 或裸 base64
- `prefix` 只允许字母数字连字符，会做文件名前缀
- 服务端会校验**文件魔数**，不是图片直接 400

### 读取

```
GET /media/<文件名>
```

**注意是 `/media/` 不是 `/api/assets/`**。

这条件路由挂在**免鉴权**的静态前缀下。原因：`<img src>` 没法携带
`Authorization` 头，如果图片在 `/api` 下受鉴权保护，浏览器拿不到 token，图会全裂。

安全性上这是可接受的：图片属于内容库（所有登录用户本来就能读角色卡），
不包含存档等私有数据。

> **为什么前缀是 `/media/` 而不是直观的 `/assets/`**
>
> Vite 打包产物本身就放在 `apps/web/dist/assets/`，也挂在这个服务器的根前缀下。
> 如果内容图片也用 `/assets/`，两个静态插件会抢同一个前缀 —— **先注册的吃掉全部请求**：
> JS/CSS 请求被路由到图片目录，找不到文件就返回 404 JSON，
> 浏览器于是报「模块的 MIME 类型是 application/json」，整页白屏。
>
> 这个坑真的踩过。`tools/check-images.mjs` 里有一条回归断言守着它。

### 删除

```
DELETE /api/assets/<文件名>     ← 仅 admin
```

### 统计

```
GET /api/assets
→ { "count": 12, "bytes": 1843200 }
```

## 前端用法

### 上传一张图

```ts
import { uploadImage } from '@/utils/image';

const path = await uploadImage(file, { prefix: 'chr', maxEdge: 512 });
// path === 'assets/chr-xxx.png'
```

内部做了三件事：读 File → canvas 压缩 → base64 上传。

### 拼成可访问 URL

```ts
import { assetUrl } from '@/utils/image';

assetUrl('assets/chr-xxx.png')  // → '/media/chr-xxx.png'
assetUrl(null)                   // → ''
```

外链（`http://` 或 `data:`）会原样返回，所以也支持外部头像 URL。

### 显示头像（推荐用组件）

```vue
<WtAvatar
  :image="character.avatarImage"
  :icon="character.avatarIcon"
  :color="character.avatarColor"
  :size="56"
  shape="round"
/>
```

组件内部处理了三件事：

1. 有图片 → 显示图片
2. 没有图片 → 显示图标 + 底色
3. **图片加载失败 → 自动回落到图标**（不会出现裂图）

`size` 接受数字（px）或字符串；`shape` 是 `full`（圆形）或 `round`（圆角方形）。

## 各处的显示位置

| 位置 | 显示什么 |
|---|---|
| 角色列表卡片 | `avatarImage` 或图标 |
| 开局选卡对话框 | 同上 |
| **阅读器消息气泡** | 玩家侧用角色卡头像；叙述者侧用规则包图标 |
| 跑团侧面板 | 同上 |
| 世界书编辑器 | 条目配图预览 |
| **阅读器（世界书命中）** | 命中条目的配图缩略图，点击放大 |

---

## 世界书配图的完整链路

```
1. 编辑者在世界书编辑器上传图片
   → POST /api/assets → assets/wb-xxx.png
   → 写进 entry.image

2. 推演时该条目被扫描命中
   → play.ts 把 loreHits 转成 loreHitDetails（含 image）
   → 写进 message.meta.loreHitDetails

3. 前端 MessageBubble 渲染
   → loreImages computed 过滤出有图的条目
   → 显示缩略图，点击打开灯箱
```

### 关键：配图不参与提示词

`image` 字段**完全不进 system prompt**，也不占 `tokenBudget`。
它纯粹是给人看的。

所以给条目加图不会挤压上下文预算，可以放心加。

## 数据模型变更

新增的字段（都已带 `?`，老数据不需要迁移）：

| 类型 | 字段 |
|---|---|
| `CharacterCard` | `avatarImage?: string \| null` |
| `WorldBookEntry` | `image?: string`、`imageCaption?: string` |
| `MessageMeta` | `loreHitDetails?: LoreHitDetail[]` |

`LoreHitDetail` 是新增的导出类型：

```ts
interface LoreHitDetail {
  name: string;
  image?: string;
  caption?: string;
}
```

旧的 `loreHits: string[]` **保留不变**，仍然只存名字，
给「调试面板」这类只想知道命中名字的地方用。

## SillyTavern 互通

图片字段放在 `extensions.worldtree` 里：

```json
{
  "extensions": {
    "worldtree": {
      "image": "assets/wb-xxx.png",
      "imageCaption": "霍格沃茨城堡"
    }
  }
}
```

其它工具会原样保留这层 `extensions`，导回来不丢。

**但图片文件本身不会被打包** —— 导出 JSON 只导出路径。
跨机器分享时要额外提供 `assets/` 里的文件。

## 排障

| 现象 | 原因 |
|---|---|
| 上传返回 400「无法识别为图片」 | 文件不是真图片（只看扩展名不算） |
| 上传返回 413 | 超过 8MB |
| 图片裂开 | 用了 `/api/assets/` 而不是 `/media/` |
| 图片裂开但没报错 | `assets/` 里文件缺失，组件已回落到图标 |
| 迁移后图全没 | 只拷了 JSON 没拷 `content/assets/` |

### 验证一张图是否存在

```bash
curl -I http://127.0.0.1:5174/media/chr-xxx.png
# 200 → 存在；404 → 缺失
```

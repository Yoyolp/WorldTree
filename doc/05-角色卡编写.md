# 05 · 角色卡编写

角色卡兼容 **SillyTavern chara_card_v2**，另加一批平台扩展字段。

---

## 文件位置

```
content/characters/
  ├─ lin-yan.json      ← JSON 角色卡
  └─ hp-first-year.png ← PNG 角色卡（数据藏在 tEXt chunk 里）
```

两种格式都能被扫描到，行为一致。

---

## ST V2 基础字段

这些是标准字段，和 SillyTavern 完全对齐：

| 字段 | JSON 键 | 说明 |
|---|---|---|
| 名字 | `name` | 角色名 |
| 描述 | `description` | 外貌、身份、背景 |
| 性格 | `personality` | 性格概要 |
| 场景 | `scenario` | 初始情境 |
| 开场白 | `firstMes` / `first_mes` | 第一条消息 |
| 对话示例 | `mesExample` / `mes_example` | few-shot 示例，影响说话风格最大 |
| 作者备注 | `creatorNotes` / `creator_notes` | 仅作者可见，不进提示词 |
| 系统提示 | `systemPrompt` / `system_prompt` | 覆盖全局系统提示 |
| 历史后置指令 | `postHistoryInstructions` / `post_history_instructions` | 插在历史之后 |
| 备选开场 | `alternateGreetings` / `alternate_greetings` | 字符串数组 |
| 标签 | `tags` | 影响分院判定 |
| 作者 | `creator` | |
| 版本 | `characterVersion` / `character_version` | |
| 扩展 | `extensions` | 原样保留未知字段 |

文件名与字段名两种写法都支持（服务端归一化时会补）。

## 平台扩展字段

放在 `extensions.worldtree` 里（导出时），读入时也接受顶层同名键。

| 字段 | 类型 | 说明 |
|---|---|---|
| `avatarIcon` | string | Material Icons 名，**没有头像图片时**的占位 |
| `avatarColor` | string | 头像底色（`#4f6f52`） |
| `avatarImage` | string \| null | **头像图片路径**（`assets/chr_xxx.png`） |
| `isPlayer` | boolean | 是否为玩家角色（调查员） |
| `sheet` | CocSheet | 跑团面板，结构由规则书写 |
| `abilities` | CharacterAbility[] | 能力（含金手指） |
| `characterBookId` | string \| null | 绑定的世界书 |

### 头像的优先级

```
avatarImage（有就用图片）
    ↓ 没有
avatarIcon + avatarColor（图标 + 底色）
```

图片加载失败时也会自动回落到图标，不会出现裂图。

---

## 头像图片

### 在网页上设置

「角色卡」→ 选择角色 → 基本标签 → 头像区点「上传图片」。

- 自动压缩到最长边 512px
- 存到 `content/assets/chr-xxx.png`
- 写回 `avatarImage`

### 手动放文件

把图片放进 `content/assets/`，然后在角色卡 JSON 里写：

```json
{ "avatarImage": "assets/my-character.png" }
```

### 显示位置

设置后自动生效于：

- 角色列表卡片
- 开局选卡对话框
- **阅读器消息气泡**（玩家这一侧）
- 跑团面板
- PNG 角色卡导出（会用作底图）

详见 [06-图片与附件](./06-图片与附件.md)。

## 跑团面板（`sheet`）

**面板的结构由规则书决定，不是平台写死的。** 这一节描述的是数据形状；
「有哪些属性、哪些资源」请看角色卡所属规则书的 `sheetSchema`（见 [04-规则插件](./04-规则插件.md#角色面板结构-sheetschema)）。

下面是一张 COC 卡（`coc7` 规则书）：

```json
{
  "sheet": {
    "rulePackId": "coc7",
    "attributes": {
      "STR": 45, "CON": 50, "SIZ": 40,
      "DEX": 65, "APP": 50, "INT": 70,
      "POW": 55, "EDU": 55, "LUCK": 60
    },
    "skills": [
      { "name": "侦查", "value": 60, "occupation": true },
      { "name": "聆听", "value": 45 },
      { "name": "图书馆使用", "value": 50 }
    ],
    "hp": 9, "hpMax": 9,
    "mp": 11, "mpMax": 11,
    "san": 55, "sanMax": 99,
    "luck": 60, "luckMax": 60,
    "conditions": [],
    "items": ["手电筒", "笔记本"]
  }
}
```

一张 D&D 卡（`dnd5e` 规则书）则是：

```json
{
  "sheet": {
    "rulePackId": "dnd5e",
    "attributes": { "STR": 16, "DEX": 14, "CON": 15, "INT": 10, "WIS": 12, "CHA": 8 },
    "skills": [
      { "name": "运动", "value": 15 },
      { "name": "察觉", "value": 13 }
    ],
    "resources": { "ac": 12, "spell1": 2, "spell1Max": 2 },
    "conditions": [],
    "items": ["长剑", "皮甲", "火把 ×5"]
  }
}
```

### 字段说明

| 字段 | 说明 |
|---|---|
| `rulePackId` | **这份面板按哪本规则书建的**。省略时按 `coc7` 处理（历史默认） |
| `attributes` | 任意键值。具体有哪些键由规则书的 `sheetSchema.attributes` 决定 |
| `skills` | 技能数组，`occupation` 标记职业技能 |
| `hp` / `hpMax` | 生命值（内置资源，所有带面板的规则都用它） |
| `mp` / `mpMax` | 魔法值 / 灵力（内置，没有就填 0） |
| `san` / `sanMax` | 理智值（内置，非 COC 体系填 0） |
| `luck` / `luckMax` | 幸运（可消耗改判） |
| `resources` | **其它资源**，键名自定；上限键名为 `<key>Max` |
| `conditions` | 状态标签（重伤、临时疯狂等） |
| `items` | 随身物品 |

> `hp/mp/san/luck` 之所以还留在平铺字段上，纯粹是为了让老存档不用迁移。
> 新规则书的资源都走 `resources`。

### 怎么知道该填哪些字段

在角色卡编辑页的「面板」标签里选一本规则书，界面会直接列出该书声明的
属性、资源、技能与派生值 —— 照着填即可，不用背字段名。

也可以问接口：

```bash
curl /api/rulepacks           # 每本规则包的 sheetSchema
```

### 技能查表的兜底顺序

`resolveSkillValue` 依次尝试：

```
精确匹配技能名 → 模糊包含匹配 → 属性名匹配 → 规则包的 difficultyPresets → 50
```

所以没有面板也能跑剧本（`script-lite` 就是靠 `difficultyPresets` 固定 50/30/15）。
「属性名匹配」这一条让 D&D 可以直接写「力量检定」「DEX 检定」而不用先建技能。

## 能力（`abilities`）

能力不是「写进提示词的一句话」，是引擎真会计算的东西。

```json
{
  "abilities": [
    {
      "id": "parseltongue",
      "name": "蛇佬腔",
      "kind": "cheat",
      "description": "你能与蛇交谈，它们愿意为你传递消息。",
      "effect": {
        "checkBonus": [{ "skill": "话术", "value": 20 }],
        "grantsFlags": ["蛇佬腔"],
        "cost": { "san": 1 },
        "onUseNarrative": "你的喉咙里发出低沉的嘶声，空气温度仿佛降了一度。"
      },
      "uses": { "max": 3, "recharge": "scene" },
      "unlocked": true,
      "inheritable": true
    }
  ]
}
```

### `kind` 可选值

| 值 | 中文 | 图标 |
|---|---|---|
| `cheat` | 金手指 | `auto_awesome` |
| `skill` | 技能 | `psychology` |
| `talent` | 天赋 | `stars` |
| `item` | 物品 | `inventory_2` |
| `curse` | 诅咒 | `warning` |

### `effect` 字段

| 字段 | 说明 |
|---|---|
| `checkBonus` | 检定加值 `[{ skill, value }]` |
| `attributeBonus` | 属性加值 `[{ attr, value }]` |
| `grantsFlags` | 使用后自动获得的标记 |
| `cost` | 使用代价（`san` / `hp` / `mp` / `luck`） |
| `onUseNarrative` | 注入叙事的提示 |

### `uses` 次数

```json
"uses": { "max": 3, "recharge": "scene" }
```

`recharge` 可选 `turn`（每回合恢复）或 `scene`（场景变化时恢复）。
次数用尽后前端会置灰。

### 检定明细会写明加值来源

```
掷出 87，目标 70（能力加值 +20）
```

## 开局选角色卡（`playerCardMode`）

世界可以声明主角卡是否写死：

```json
{ "playerCardMode": "fixed" }
```

| 值 | 含义 |
|---|---|
| `open`（默认） | 世界队内的角色 + 角色库里的卡都能当主角 |
| `fixed` | 只能用本世界自带的角色卡；外来卡和「不绑定」会被服务端拒绝 |

## 分院（世界级配置，但按角色卡判定）

世界可以声明分院规则，进入世界线时按角色卡的**标签 / 能力 / 描述**判归属：

```json
{
  "sorting": {
    "houses": [
      { "name": "格兰芬多", "keywords": ["勇敢", "勇气", "胆量", "正义", "冲动"] },
      { "name": "赫奇帕奇", "keywords": ["忠诚", "勤奋", "耐心", "善良", "踏实"] },
      { "name": "拉文克劳", "keywords": ["聪明", "好奇", "求知", "理性", "观察"] },
      { "name": "斯莱特林", "keywords": ["野心", "精明", "算计", "蛇佬腔"] }
    ],
    "fallback": "拉文克劳"
  }
}
```

判定结果写成标记 `分院·拉文克劳`，剧本里可以用 `{require=flag:分院·拉文克劳}` 做分支。

**所以角色卡的 `tags` 和 `description` 会影响分院结果** —— 想分到某个学院，
就把对应关键词写进标签或描述里。

## 继承（跨作品延续）

角色卡上的能力可以设为 `"inheritable": true`。
走到结局节点时生成的 `LegacySnapshot` 会带上：

| 字段 | 来源 |
|---|---|
| `abilities` | 标了 `inheritable` 的能力 |
| `sheet` | 最终面板（属性 / 技能 / 物品） |
| `relationships` | `vars` 里的 `rel.<名字>` 约定 |
| `flags` | 关键选择标记 |
| `vars` | 对世界造成的改变 |
| `summary` | 前情提要 |

## PNG 角色卡

PNG 角色卡 = 一张图片 + 藏在 `tEXt` chunk 里的 JSON。

- **导出**：`GET /api/characters/:id/export-png`
  - 有 `avatarImage` 且是 PNG → 用头像当底图
  - 否则 → 生成纯色底图
- **导入**：`POST /api/characters/import-png`（传 base64）

导出的 PNG 可以直接拖进 SillyTavern 使用。

## 编写建议

### 1. `mesExample` 比 `description` 更影响说话风格

模型模仿示例的力度远大于遵守形容词描述。想让它说话简短，就给简短的对话示例。

### 2. 描述里写「不会做什么」

比「会做什么」更能约束行为：

```
她不会主动解释自己的动机，被追问时会转移话题。
```

### 3. 第一个 `firstMes` 决定开局基调

它会作为历史里的第一条 assistant 消息进入上下文。

### 4. 标签会被分院读取

`tags` 不只是分类，它参与 `sorting` 的关键词判定。

### 5. 适龄约束（如果做少年角色）

HP 示例卡的做法值得参考：STR/CON/SIZ 偏低（30~45）、EDU 上限约 60，
但 DEX 与 LUCK 高，并且描述里写明「孩子问问题，大人往往愿意回答」——
用面板数值 + 描述共同表达「他做不到什么」。

## 与 SillyTavern 互通

| 操作 | 接口 |
|---|---|
| 导出 JSON | `GET /api/characters/:id/export` |
| 导出 PNG | `GET /api/characters/:id/export-png` |
| 导入 JSON | `POST /api/characters/import` |
| 导入 PNG | `POST /api/characters/import-png` |

平台扩展都在 `extensions.worldtree` 里，其它工具会原样保留，导回来不丢。

**注意**：`avatarImage` 存的是相对路径。跨实例迁移时要**把 `content/assets/` 一起拷过去**，
否则图片会裂（会回落到图标，不会报错）。

按文件逐个说明「它管什么、什么时候会被调用、改它要注意什么」。

## packages/shared（纯函数层）

### `resolution.ts` —— 判定策略（插件化的核心）

四类策略，每类是一个纯函数：

| 策略 id | 语义 | 适用 |
|---|---|---|
| `d100-threshold` | 1d100 ≤ 目标 | COC 全系 |
| `dN-threshold` | 1dN ≤ 目标 | DnD 属性检定、叙事包 |
| `dice-pool` | n 个骰子，数成功数 | WoD、影之诗 |
| `sum-compare` | 加总值 vs 难度 | PbtA、Savage Worlds |

每个策略返回 `ResolutionResult`：

```ts
{
  roll: { dice, modifier, value },
  basis,        // 用于分级判定的数值
  target,       // 展示用目标值
  outcome?,     // 策略自己给的结果（骰池/加总值必须给）
  detailParts,  // 「掷出 42，目标 60」这类片段
}
```

**关键设计**：`outcome` 是可选的。

- 阈值类（d100/dN）**不给** `outcome`，交给 `cocOutcome()` 按目标值分级
- 骰池与加总值**必须给**，因为它们的「成功」方向跟阈值相反
  （骰池是成功数越多越好，加总值是总和越大越好；阈值是骰值越小越好）

这一点踩过坑：一开始都交给 `cocOutcome` 统一判，结果骰池掷出 3 个成功（需 2 个）被
判成「失败」，因为 3 > 2 在阈值语义里意味着超过目标值。

**扩展**：`registerStrategy()` 可以注册自定义策略，见 [04-规则插件](./04-规则插件.md)。

### `dice.ts` —— 掷骰与检定入口

`performCheck()` 是统一入口：查策略 → 掷骰 → 判等级 → 组装 `CheckResult`。

```ts
performCheck({ skill, target, difficulty, bonus, rng, pack })
```

要点：

- `target` **保持技能原值**，不做难度折减
  （COC7 的难度靠「成功等级秩比较」实现，再除一次等于应用两遍）
- `cocOutcome()` 支持 `outcomeBands` 自定义分档表
- `spendLuckToSucceed()` 每 1 点幸运换 1 点差额
- `rollFormula()` 支持 `2d6+3` 这类表达式

---

### `rulepacks.ts` —— 规则包注册表

- 内置四个包（`coc7` / `coc-d100` / `script-lite` / `narrative`）
- `registerRulePack()` 供插件加载器注册
- `resetRulePacks()` 清掉插件，回到内置状态
- `getRulePack(id)` 未知 id **回落 coc7**（不让作者写错 id 就把推演打成异常）

---

### `events.ts` —— 事件引擎

`fireEvents()` 的流程：

1. 按 `trigger` 过滤
2. 检查 `once` / `cooldown`
3. 求值条件组（AND）
4. 按 `priority` 排序
5. 逐个掷概率，**每回合最多 2 个**
6. 记录 `EventFireRecord`（含随机 roll，可复现）

支持的触发时机：`turn_start` / `turn_end` / `enter_node` / `player_action` / `before_narration`

---

### `script-dsl.ts` —— 剧本 Markdown 编译

人写友好的 Markdown → 节点图 JSON，也支持反向序列化（`serializeScript`）。

```markdown
# 第一节车厢 · 广播 {id=car1}

正文……

::: director
给 AI 的导演备注
:::

::: event 第一次广播 once chance=100%
广播里混进了一个不属于广播员的笑声。
- san: -1
:::

- [留在原地] -> seat {flag=谨慎} {check=侦查 常规}
```

编译产物是 `StoryScript`，其中 `rulePackId` 从 front-matter 的 `rulePack` 读。

---

### `protocol.ts` —— 元数据解析（容错核心）

模型输出正文 + `<<<WT_META>>>{...}<<<END_META>>>`。但小模型经常写不对，所以：

| 层级 | 处理 |
|---|---|
| 1 | 标准标记 |
| 2 | 没写标记，从尾部抓裸 JSON |
| 3 | JSON 被截断 → 自动补引号括号 `repairTruncatedJson` |
| 4 | `>>> 选项A / 选项B` 行内选项 → 剥离并转成真按钮 |
| 5 | 清掉 `</think>`、` thinking…` 残留 |
| 6 | 都失败 → 服务端发一次小请求让模型「只转 JSON」 |

也提供 `estimateTokens()`：中文按 1 字 1 token 估算（**故意高估**，低估会导致静默超窗）。

### `coc-checks.ts` —— COC 深度规则

理智检定、对抗检定、战斗、团队检定、连续检定、技能成长。
比 `dice.ts` 更上层，直接用 `rollDie` / `rollDelta`。

---

### `abilities.ts` —— 能力计算

能力不是「写进提示词的一句话」，而是引擎真会算的东西：

```ts
effect: {
  checkBonus: [{ skill: '话术', value: 20 }],  // 检定目标值 +20
  grantsFlags: ['蛇佬腔'],
  cost: { san: 1 },
  onUseNarrative: '你的喉咙里发出低沉的嘶声…'
}
```

`activeAbilities()` 合并角色卡自带 + 继承来的能力；
`resetUsesFor()` 按 `recharge`（turn / scene）恢复次数。

---

### `legacy.ts` —— 继承存档

走到结局节点时生成 `LegacySnapshot`（能力 / 面板 / 关系 / 标记 / 变量 / 前情），
续作世界通过 `inheritance.accepts` 声明接收哪些字段。

---

### `sillytavern.ts` —— ST V2 双向转换

- 角色卡：`toSTCard` / `fromSTCard`，平台扩展放 `extensions.worldtree`
- 世界书：`toSTWorldInfo` / `fromSTWorldInfo`
- PNG 角色卡：`embedCharaInPng` / `extractCharaFromPng`（tEXt chunk）

**平台扩展字段都会被带出去**（否则导回平台就丢了）：`avatarIcon`、`avatarImage`、
`avatarColor`、`abilities`、`sheet`、`image`、`imageCaption`。

## apps/server（有状态层）

### `index.ts` —— 启动装配

顺序很重要：

```
ensureDirs → getDb → ensureAdmin → registerAuth（钩子）
  → auth 路由 → assets 路由 → 业务路由
  → /assets 静态挂载（免鉴权）
  → Web 静态 → seed → syncAllContentAsync → listen → 探测上下文
```

**为什么 assets 静态挂载免鉴权**：`<img src>` 没法带 Bearer 头。

---

### `db.ts` —— Schema 与迁移

- `SCHEMA` 里全是 `CREATE TABLE IF NOT EXISTS`
- `ensureColumn()` 给老库补列（`rooms.kp_mode`、`sessions.owner_id` 等）
- **索引必须在补列之后建**，否则老库会报 `no such column`

---

### `repo.ts` —— 会话 / 消息 CRUD

重点方法：

| 方法 | 用途 |
|---|---|
| `messages.append()` | 追加消息并维护 `seq` |
| `messages.saveState()` | 保存某条消息的完整状态快照 |
| `messages.stateAt()` | 取那一刻的状态（分叉/回退用） |
| `messages.copyUpTo()` | 分叉时复制历史 + 快照 |
| `messages.truncateAfter()` | 回退时删掉之后的消息 |
| `sessions.remove()` | 级联删消息与快照 |

---

### `engine/resolver.ts` —— 会话级规则引擎

单回合内的纯逻辑，**不碰数据库**：

- `parseIntent()` 意图推断（只建议，不裁定）
- `applyScriptEffect()` 状态变更（不可变，返回新对象）
- `enterNode()` / `applyChoice()` 节点推进
- `resolveEvents()` 事件判定
- `runCheck()` 检定（含幸运改判、孤注一掷、失败推进）
- `initialState()` / `endTurn()` 生命周期

---

### `services/play.ts` —— 单回合推演（最核心）

`runTurn(req)` 是一个 `AsyncGenerator<StreamEvent>`，边算边吐 SSE。
完整流程见 [01-程序结构](./01-程序结构.md#一回合推演的完整数据流)。

另外两个函数：

- `generateOutro()` 结局收尾散文（离线时不生成）
- `fallbackNarration()` 模型挂了时的离线旁白

**注意**：`runTurn` 里所有对 `state` 的修改都是重新赋值（不可变），
不要在中间直接改 `state.xxx`，否则后续快照会污染。

---

### `llm/prompt.ts` —— 提示词编排

`buildChatTurns()` 的预算逻辑：

```
win         = 真实 contextWindow
outReserve  = min(maxTokens, win × 0.33)
promptTokens= max(900, (win - outReserve - 128) × 0.88)
sysCap      = promptTokens × 0.6    ← 系统提示最多占 60%，给历史留余量
```

系统提示超预算时**逐级瘦身**：

```
input → dropLore（丢世界书）→ dropBig（丢节点目录/继承/事件）→ compactAll（压成摘要）
```

绝不让服务端从**头部**截断——那会把输出格式要求一起剪掉，模型随即失范。

`packInstructions()` 现在读 `pack.instructions`，不再按 id 硬编码。

---

### `llm/client.ts` —— 三种协议适配

| provider | 端点 | 特殊情况 |
|---|---|---|
| OpenAI 兼容 | `/chat/completions` | 绝大多数服务 |
| Anthropic | `/messages` | `x-api-key` 头 |
| Ollama | `/api/chat` | **唯一能下传 `num_ctx` 的入口** |

Ollama 的 `/v1/chat/completions` 不接受 `num_ctx`，所以走原生接口。
`isOllama()` 只认 11434 端口，避免把 llama.cpp / LM Studio 误判成 Ollama（它们没有 `/api/chat`）。

---

### `content/store.ts` —— 文件 ↔ 数据库

- `loadWorldFile` / `loadCharacterFile` / `loadWorldBookFile` / `loadScriptFile`：读文件并归一化
- `syncAllContent()`：全量 `DELETE` + `INSERT`（同步版）
- `syncAllContentAsync()`：同步 + 加载规则插件（启动与手动重扫用）

归一化时会补齐所有缺省字段，**老文件不需要手改**。

**已知问题**：`syncAllContent` 没有包事务，中途抛错会留下半空表。

---

### `content/rulepack-plugins.ts` —— 规则插件加载

动态 `import()` `content/rulepacks/*.{js,mjs,ts}`，加时间戳绕开 ESM 缓存（改了重扫即生效）。

校验后 `registerRulePack()`；插件也可导出 `strategy` 注册自定义判定。

---

### `content/png.ts` —— PNG 角色卡

有头像 PNG 时**用头像当底图**（导出的卡片在 ST 里直接显示立绘），
否则生成纯色底图。两种都把 ST V2 JSON 塞进 `chara` tEXt chunk。

---

### `lib/lore.ts` —— 世界书扫描

1. 取最近 `scanDepth` 条消息拼窗口
2. 主关键词命中 + 选择性逻辑（AND / OR / NOT）
3. 常驻条目直接入选
4. 概率判定
5. 同组只保留优先级最高的
6. 按优先级排序，在 `tokenBudget` 内注入

跨回合状态（`cooldowns` / `sticky`）存在 `state.lore`。

---

### `lib/session-lock.ts` —— 串行锁

两个 API：

- `withLock(key, fn)`：整个任务包起来（JSON 接口用）
- `acquire(key)` / `release()`：手动版（SSE 用，因为要先吐 header）

单进程内存实现即可，本项目就是单进程 Fastify。

---

### `lib/auth.ts` / `lib/access.ts` —— 鉴权与归属

- `registerAuth()` 注册 `onRequest` 钩子，白名单外全部要登录
- `requireSessionAccess()` 越权返回 **404 而不是 403**（不泄露存在性）
- `requireAdmin()` 非 admin 抛 403

---

### `settings.ts` —— 配置与上下文探测

- `getLlmConfig()` 会用探测到的真实窗口**夹住**用户填的数字
- `detectContextWindow()` 支持 llama.cpp（`/props`）与 Ollama（`/api/ps`）
- `renderSafety()` 把内容安全设置渲染成提示词红线

---

### `services/combat.ts` / `services/rooms.ts`

战斗：先攻排序、攻击对抗闪避、伤害、重伤、濒死。
房间：一名 KP + 最多 7 名玩家，按座位轮流，SSE 广播。

# 04 · 规则插件

规则书是**可插拔的可执行模块**。加一本新规则书 ≈ 在 `content/rulepacks/` 放一个 `.js` 文件，不用改平台代码。

---

## 快速上手

### 最小插件

```js
// content/rulepacks/my-rules.js
export default {
  id: 'my-rules',
  name: '我的规则书',
  description: '一句话说明',
  dieFaces: 100,
  strategy: 'd100-threshold',
  difficulties: false,
  bonusPenalty: false,
  luckSpend: false,
  pushedRolls: false,
  autoCheck: true,
  failForward: true,
  sanity: false,
  combat: false,
};
```

启动日志会显示 `规则包 N（插件 M）`，世界编辑器的规则包列表里就多出一张卡。

---

## 文件位置与加载

```
content/rulepacks/
  ├─ my-rules.js     ← .js / .mjs / .cjs / .ts 都支持
  └─ fate.ts
```

- **启动时**自动加载
- **`POST /api/content/sync`** 重新加载（用 mtime 绕开 ESM 缓存，改完即生效）
- **删掉文件** 重启后规则包消失（`resetRulePacks()` 回到内置四包）

### 导出形式

```js
export default { id: 'x', name: '...', ... }        // 对象
export default () => ({ id: 'x', ... })             // 工厂函数
export const pack = { id: 'x', ... }                // 具名导出
```

三种都支持。

## RulePack 完整字段

### 必填

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 唯一标识，只允许字母数字 `_` `.` `-` |
| `name` | string | 显示名 |

### 判定（核心）

| 字段 | 类型 | 说明 |
|---|---|---|
| `strategy` | string | 判定策略 id，见下表 |
| `strategyParams` | object | 传给策略的参数 |
| `dieFaces` | number | 骰面数（`dN-threshold` 真正会用它） |
| `outcomeBands` | array | 自定义分档表（见下） |
| `criticalValue` | number | 大成功骰值（默认 1） |
| `fumbleValue` | number | 大失败骰值（默认 100） |
| `fumbleRange` | object | 低技能扩大大失败区间 |
| `simpleOutcome` | boolean | 只分成功/失败两档 |
| `difficultyPresets` | object | 无面板时的固定目标值 |

### 能力开关

| 字段 | 默认 | 说明 |
|---|---|---|
| `difficulties` | false | 支持困难/极难难度 |
| `bonusPenalty` | false | 支持奖励/惩罚骰 |
| `luckSpend` | false | 支持消耗幸运改判 |
| `pushedRolls` | false | 支持孤注一掷 |
| `autoCheck` | true | 自动从玩家行动推断检定 |
| `failForward` | true | 失败也推进剧情 |
| `sanity` | false | 理智机制（生成面板） |
| `combat` | false | 战斗流程 |

### 展示

| 字段 | 说明 |
|---|---|
| `icon` | Material Icons 名（默认 `extension`） |
| `instructions` | **注入系统提示的规则段落** |
| `sheetSchema` | **角色面板结构**，见下一节 |

> **`instructions` 很重要**：平台不再按 id 硬编码规则说明。
> 不写的话会用一段通用兜底文案，模型对规则的理解会很模糊。

### 面板相关的钩子

| 字段 | 默认 | 说明 |
|---|---|---|
| `sanityResource` | `'san'` | 理智值存在哪个资源键上 |
| `sanityBoutAttribute` | `'INT'` | 临时疯狂时做哪项属性检定 |
| `initiativeAttribute` | `'DEX'` | 战斗先攻用哪个属性 |

这三项是为了让「理智值叫 Resolve」「先攻看敏捷」这类换皮体系不用改代码。

## 角色面板结构（`sheetSchema`）

**这是「支持任意规则书」的关键。** 以前面板写死成 COC 的九属性 + HP/MP/SAN，
D&D 用不了。现在面板的结构由规则书声明，平台只负责渲染与存值。

不写 `sheetSchema` 表示「这本规则不用跑团面板」（`narrative`、`script-lite` 就是）。

```js
sheetSchema: {
  label: 'D&D 5e 冒险者',      // 面板副标题
  attrLabel: '属性',            // 分区标题，都可以省
  resourceLabel: '状态',
  skillLabel: '技能（点击检定）',

  // 属性：键名随便起，中文也行
  attributes: [
    { key: 'STR', label: '力量', abbr: 'STR', min: 1, max: 30, default: 10, roll: '4d6', group: '身体', hint: '影响近战' },
    { key: 'DEX', label: '敏捷', abbr: 'DEX', min: 1, max: 30, default: 10, roll: '4d6', group: '身体' },
    { key: 'CON', label: '体质', abbr: 'CON', min: 1, max: 30, default: 10, roll: '4d6', group: '身体' },
    { key: 'INT', label: '智力', abbr: 'INT', min: 1, max: 30, default: 10, roll: '4d6', group: '心智' },
    { key: 'WIS', label: '感知', abbr: 'WIS', min: 1, max: 30, default: 10, roll: '4d6', group: '心智' },
    { key: 'CHA', label: '魅力', abbr: 'CHA', min: 1, max: 30, default: 10, roll: '4d6', group: '社交' },
  ],

  // 资源：有 maxFormula 就自动推导
  resources: [
    { key: 'hp', label: 'HP', maxFormula: '10 + floor((CON-10)/2) * 2', color: '#b03a2e' },
    { key: 'ac', label: 'AC', initFormula: '10 + floor((DEX-10)/2)', bar: false },  // 无上限，显示为数字
    { key: 'spell1', label: '一环法术位', maxFormula: '2', color: '#2e6db0' },
  ],

  // 技能：baseFormula 决定新建时的值
  skills: [
    { key: '察觉', label: '察觉', baseFormula: '10 + floor((WIS-10)/2)', attribute: 'WIS', group: '感知' },
    { key: '隐匿', label: '隐匿', baseFormula: '10 + floor((DEX-10)/2)', attribute: 'DEX', group: '身体' },
  ],
  freeSkills: true,     // 允许玩家自己加技能（默认 true）
  skillMax: 40,         // 编辑页输入框上限（默认 99）

  // 只读派生展示
  derived: [
    { key: 'STRmod', label: '力量调整', formula: 'floor((STR-10)/2)' },
    { key: 'passivePerception', label: '被动察觉', formula: '10 + floor((WIS-10)/2)' },
  ],
}
```

### 字段速查

**attributes**

| 字段 | 说明 |
|---|---|
| `key` | 数据键，存进 `sheet.attributes[key]` |
| `label` / `abbr` | 中文名 / 角标 |
| `min` / `max` | 编辑范围（默认 1 ~ 99） |
| `default` | 新建时的初始值 |
| `roll` | 「随机生成」时用的骰式，如 `3d6*5`、`4d6` |
| `group` | 分组，同组排在一起 |
| `hint` | 悬停说明 |

**resources**

| 字段 | 说明 |
|---|---|
| `key` | 资源键。`hp`/`mp`/`san`/`luck` 是内置键，其余进 `sheet.resources` |
| `maxFormula` | 上限公式，如 `(CON+SIZ)/10` |
| `initFormula` | 当前值公式，省略则等于上限 |
| `color` | 进度条颜色 |
| `bar` | `false` 时渲染成数字徽章（AC、速度这类无上限值） |
| `dangerRatio` | 低于该比例标红，默认 0.25 |
| `min` / `max` | 数值上下界 |

**skills**

| 字段 | 说明 |
|---|---|
| `key` / `label` | 键与显示名 |
| `baseFormula` | 基准值公式，如 `DEX/2`、`10+WIS` |
| `default` | 无公式时的默认值 |
| `attribute` | 关联属性（展示用） |
| `group` | 分组 |
| `description` | **一句话效果**，展示在百科的技能卡片上 |
| `effectText` | **详细效果说明**，支持 Markdown，百科点开技能时展示 |
| `tags` | 分类标签，如 `['社交', '谎言']`，百科里可用于筛选 |
| `examples` | 典型用法示例，百科里作为「什么时候用」 |

> `description` / `effectText` / `tags` / `examples` **只是给玩家读的说明，不参与判定**。
> 想让技能真的影响掷骰，用 `baseFormula` 改基础值，或用角色卡的
> `abilities[].effect.checkBonus` 加值。

示例（摘自 `content/rulepacks/dnd5e.js`）：

```js
{
  key: '隐匿', label: '隐匿',
  baseFormula: '10 + floor((DEX-10)/2)', attribute: 'DEX', group: '身体',
  tags: ['身体', '潜行'],
  description: '躲藏、潜行、不被察觉。',
  effectText: '用于避免被发现。通常与对方的**察觉**对抗。\n\n- 成功：对方没有发现你。\n- 失败：你被发现。',
  examples: ['混进夜市的人群', '在哨兵背后潜行'],
}
```

**derived**

`{ key, label, formula, suffix? }`，只读展示，公式结果四舍五入取整。

### 公式语言

`maxFormula` / `initFormula` / `baseFormula` / `roll` / `derived.formula` 用的是
**同一个受限表达式求值器**（`packages/shared/src/formula.ts`），不是 `eval`：

- 数字、`+ - * / %`、括号
- 变量名（属性键，大小写不敏感；也能引用当前资源值，如 `hp`）
- 函数：`floor` `ceil` `round` `abs` `min` `max` `sign`
- 骰式：`NdM`，如 `3d6*5`、`1d8+2`

**不支持**属性访问、自定义函数调用、字符串 —— 所以规则书即使来自不可信来源，
也不构成任意代码执行点（对比之下，插件本身的 JS 是）。

公式写错不会让面板打不开：求值失败时该字段显示 `—`。

### 面板数据怎么存

`CocSheet` 这个名字是历史遗留（现在和 COC 无关了）：

```ts
interface CocSheet {
  attributes: Record<string, number>;   // 键由 sheetSchema 决定
  skills: { name: string; value: number }[];

  // 内置资源仍留平铺字段，老存档零迁移
  hp: number; hpMax: number;
  mp: number; mpMax: number;
  san: number; sanMax: number;
  luck?: number; luckMax?: number;

  resources?: Record<string, number>;   // 其它资源，上限键名为 `<key>Max`
  rulePackId?: string;                  // 这份面板按哪本规则书建的
  conditions: string[];
  items: string[];
}
```

**读面板不要直接摸 `sheet.hp`**，用这两个函数（它们知道内置键与扩展键的区别）：

```ts
import { resourceValue, resourceMax, withResource } from '@worldtree/shared';

resourceValue(sheet, 'hp');       // 内置键
resourceValue(sheet, 'ac');       // 扩展键，读 sheet.resources.ac
withResource(sheet, 'hp', 8);     // 不可变写入
```

### 换规则书时怎么迁移

玩家可能拿一张 COC 卡进 D&D 世界。`migrateSheet(sheet, schema)` 的规则是：

1. 能对上的键**原样保留**
2. 对不上的键**留在原处不动**（不删！可能切回去还要用）
3. schema 里有、面板里没有的键**按 default/roll 补齐**
4. 资源上限按新公式重算，当前值按比例缩放（避免出现 `120 / 10`）

结果：切一本规则书不会丢数据，多出来的字段前端只是不显示。

### 谁决定面板按哪本书渲染

角色卡自己记着 `sheet.rulePackId`。世界可以覆盖：

```ts
// 世界文件里
sheetRulePrecedence: 'character' | 'world'
```

- `character`（默认）：面板按角色卡的规则书渲染
- `world`：面板按世界的规则书渲染，角色卡多出的字段保留但不显示

**注意：这只影响「面板长什么样」。掷骰判定永远用世界的规则书** ——
否则同一世界内会出现两套成功率。

## 四类内置判定策略

### 1. `d100-threshold` —— 百分骰

掷 1d100，≤ 目标即成功。

```js
strategy: 'd100-threshold',
strategyParams: {
  bonusPenalty: true,   // 启用奖励/惩罚骰（多组十位骰取极值）
},
criticalValue: 1,
fumbleValue: 100,
fumbleRange: { below: 50, from: 96 },  // 目标<50 时 96-100 大失败
```

**成功等级**（默认按目标值折档）：

```
1                → 大成功
≤ 目标/5         → 极难成功
≤ 目标/2         → 困难成功
≤ 目标           → 成功
100              → 大失败
其余              → 失败
```

### 2. `dN-threshold` —— 单骰

掷 1dN，N 由 `dieFaces` 决定。

```js
strategy: 'dN-threshold',
dieFaces: 20,
```

这是 `narrative` 包用的策略。注意：**`dieFaces` 在这里真正生效**，
在某些历史版本里它是个死变量，所有规则包都被按 d100 掷。

### 3. `dice-pool` —— 骰池成功数

掷 N 个骰子，数「≥ 阈值」的个数，达到所需成功数即成功。

```js
strategy: 'dice-pool',
strategyParams: {
  poolSize: 7,            // 骰子个数
  poolDieFaces: 10,       // 骰面
  successThreshold: 6,     // ≥ 这个算成功
  successesNeeded: 2,      // 需要几个成功
  botchRule: 'cancel',     // 掷出 1 抵消一个成功（可选）
},
```

**成功等级**：

| 成功数 | 等级 |
|---|---|
| ≥ 需要 + 2 | 极难成功 |
| ≥ 需要 + 1 | 困难成功 |
| ≥ 需要 | 成功 |
| < 需要 | 失败 |
| 0 且开了 cancel | 大失败 |

难度会折算成「所需成功数」增加（困难 +1、极难 +2）。

### 4. `sum-compare` —— 加总值对比

掷若干骰子求和 + 修正，与难度值比较。

```js
strategy: 'sum-compare',
strategyParams: {
  diceCount: 2,
  dieSides: 10,
  modifier: 0,
  tiers: [
    { min: 10, outcome: 'regular' },   // 10+ 完全成功
    { min: 7,  outcome: 'hard' },      // 7-9 部分成功
    { min: 0,  outcome: 'fail' },      // 6- 失败
  ],
},
```

参数：

| 参数 | 说明 |
|---|---|
| `diceCount` / `dieSides` / `modifier` | 骰子数与修正值 |
| `tiers` | 分档表，从高到低匹配。**只在没有难度表时参与判定** |
| `difficultyThresholds` | 各难度的门槛，如 `{ regular: 10, hard: 15, extreme: 20 }` |
| `difficultyThreshold` | 单一门槛（没有表时用） |
| `difficultyShift` | 分档线整体推移，如 `{ hard: 3, extreme: 6 }` |
| `criticalOn` / `fumbleOn` | 某个骰面直接判大成功 / 大失败（天然 20 / 天然 1） |
| `marginGrades` | 有门槛表却没 `tiers` 时，按超出多少分档，默认 `{ hard: 5, extreme: 10 }` |

> **`tiers` 与 `difficultyThresholds` 别同时用**。
> 同时给的话 `tiers` 会被忽略 —— 否则「DC 20 但总值 10」会被对照
> `{ min: 10 }` 判成成功，难度就形同虚设。

## 自定义分档表（`outcomeBands`）

不想用默认的「目标值折档」时，直接给一张表：

```js
outcomeBands: [
  { outcome: 'critical', min: 1, max: 1 },
  { outcome: 'regular',  min: 2, max: 70 },
  { outcome: 'fail',     min: 71 },
],
```

`min` 含、`max` 含，`max` 省略表示无上界。
**给了这张表就完全按表判**，`criticalValue` / `fumbleValue` 不再生效。

## 自定义判定策略

内置四类覆盖了主流体系，但总有例外（比如 Fate 骰、矩阵骰）。
插件可以注册自己的策略：

```js
// content/rulepacks/fate.js

/** Fate 骰：4 个骰子，每个是 +1 / 0 / -1 */
export const strategy = {
  id: 'fate-dice',
  name: 'Fate 骰',
  description: '4dF：四个骰子各出 +1 / 0 / -1，求和后与难度比较。',
  resolve(ctx) {
    const faces = [-1, 0, 1];
    const dice = [];
    for (let i = 0; i < 4; i++) {
      dice.push(faces[Math.floor(ctx.rng() * 3)]);
    }
    const total = dice.reduce((a, b) => a + b, 0);
    const target = ctx.difficulty === 'hard' ? 2 : ctx.difficulty === 'extreme' ? 4 : 0;

    return {
      roll: { dice, modifier: 0, value: total },
      basis: total,
      target,
      // 绝对值越大越好；这里简化成「>= 目标即成功」
      outcome: total >= target ? 'regular' : 'fail',
      detailParts: [`${dice.map((d) => (d > 0 ? '+' : '') + d).join(' ')} = ${total}`, `难度 ${target}`],
      candidates: dice,
    };
  },
};

export default {
  id: 'fate',
  name: 'Fate Core',
  dieFaces: 6,          // 仅作展示
  strategy: 'fate-dice',
  difficulties: true,
  // ...
};
```

### 策略接口

```ts
interface ResolutionStrategy {
  id: string;
  name: string;
  description: string;
  resolve(ctx: ResolutionContext): ResolutionResult;
}

interface ResolutionContext {
  skill: string;
  target: number;              // 技能原始值（未折减）
  difficulty: 'regular' | 'hard' | 'extreme';
  bonus: number;               // 正=奖励，负=惩罚
  rng: () => number;           // ★ 必须用它，才能复现
  params: Record<string, unknown>;  // strategyParams + 平台注入的 dieFaces/bonusPenalty
  pushed?: boolean;
}

interface ResolutionResult {
  roll: { dice: number[]; modifier: number; value: number; pushed?: boolean };
  basis: number;               // 用于分级的数值
  target: number;              // 展示用目标
  outcome?: CheckOutcome;      // 可选；不给就走 cocOutcome 默认分级
  detailParts: string[];       // 展示明细
  candidates?: number[];
}
```

### 两个必须遵守的约束

**1. 只能用 `ctx.rng()`，不能用 `Math.random()`**

否则同一存档点重演结果不一致，分叉就复现不了。

**2. 「越大越好」的策略必须自己给 `outcome`**

默认分级器 `cocOutcome()` 按「骰值 ≤ 目标」判成功。
骰池和加总值是反过来的——不给 `outcome` 会被判反。

这个坑真实踩过：骰池掷出 3 个成功（需要 2 个），
因为 `3 > 2` 被判成「失败」。

## 难度怎么表达

有两种方式，**只能选一种**，否则会叠加：

### 方式 A：成功等级秩比较（COC 风格）

`target` 保持技能原值，靠「困难检定要掷出困难成功才算过」实现。

```js
difficulties: true,
strategyParams: {},   // 不设 difficultyDivisor
```

### 方式 B：折减目标值

适用于没有成功等级概念的体系（骰池、加总值）。

```js
strategyParams: { difficultyDivisor: { hard: 2, extreme: 5 } }
```

`applyDifficultyDivisor()` 默认**不折减**，只有显式配置才生效。

## 常见体系配方

### COC 7 版（内置 `coc7`）

```js
strategy: 'd100-threshold',
strategyParams: { bonusPenalty: true },
criticalValue: 1,
fumbleValue: 100,
fumbleRange: { below: 50, from: 96 },
difficulties: true,
bonusPenalty: true,
luckSpend: true,
pushedRolls: true,
sanity: true,
combat: true,
```

### DnD 5e（内置示例 `dnd5e`）

D&D 是「d20 + 调整值 ≥ DC」，**越大越好**，和 `dN-threshold` 的「越小越好」方向相反。
所以不能用 `dN-threshold`，要用 `sum-compare` + 难度门槛表：

```js
strategy: 'sum-compare',
strategyParams: {
  diceCount: 1,
  dieSides: 20,
  difficultyThresholds: { regular: 10, hard: 15, extreme: 20 },  // DC
  criticalOn: 20,
  fumbleOn: 1,
},
```

完整可运行版本见 `content/rulepacks/dnd5e.js`（六属性、AC、法术位、八项派生数值）。

> 早期文档建议「把目标值设成 `21 - DC`」来硬凑方向 —— 不要这么做。
> 那样成功等级、大成功判定全都是反的，且没法表达「超出 DC 5 点算困难成功」。

### PbtA（2d6 + 属性）

```js
strategy: 'sum-compare',
strategyParams: {
  diceCount: 2,
  dieSides: 6,
  modifier: 0,
  tiers: [
    { min: 10, outcome: 'regular' },  // 10+ 完全成功
    { min: 7,  outcome: 'hard' },     // 7-9 部分成功
    { min: 0,  outcome: 'fail' },     // 6- 失败
  ],
},
failForward: true,
```

### 简化百分骰（内置 `script-lite`）

```js
strategy: 'd100-threshold',
dieFaces: 100,
simpleOutcome: true,     // 只分成功/失败，不细分困难/极难
difficultyPresets: { regular: 50, hard: 30, extreme: 15 },
failForward: true,
```

## 排障

| 现象 | 原因 |
|---|---|
| 规则包没出现在列表 | 检查启动日志有没有「加载失败」，或文件扩展名不在白名单 |
| 掷骰结果永远是 d100 | 忘了写 `strategy`，回落到了 `d100-threshold` |
| 明明成功却报失败 | 策略是「越大越好」但没给 `outcome` |
| 困难难度几乎不可能过 | `difficulties: true` 同时配了 `difficultyDivisor`，应用了两次 |
| 分叉后重演结果不同 | 策略里用了 `Math.random()` |
| 模型不理解规则 | `instructions` 没写，用的是通用兜底文案 |
| 角色卡面板是空的 | 规则书没写 `sheetSchema`，或 `attributes` 是空数组 |
| 面板字段显示 `—` | 派生/上限公式求值失败，检查变量名是否拼错 |
| 换了规则书面板还是旧的 | 角色卡的 `sheet.rulePackId` 没跟着改；编辑页点一下规则书选项再保存 |

## 安全说明

规则插件是**可执行代码**，等价于允许在服务端跑任意 JS。

- 只加载你自己信任的文件
- 不要从不可信来源下载 `.wtrules.js` 直接扔进 `content/rulepacks/`
- 插件目录不建议随内容包分发
